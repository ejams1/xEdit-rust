## Known divergences

Behaviour a script can meet where the port does not reproduce the oracle exactly. Each is a `known-difference` accepted in `probes.json` (or a `docs/PLAN.md` item); say so rather than guessing when a script trips one.

- **A record read by its name first keeps its subrecords (UPSTREAM-BUG, not reproduced; user decision 2026-10-16).** Upstream's quick init (`GetEditorID` under `mrsQuickInit`, run by `Name`/`EditorID`/`FullName`) of a record whose subrecords all lie before `QuickInitLimit` adds the required members as an internal edit and then releases the elements with the storage invalid; the record's next init collapses the storage from no elements, so the oracle's record has 0 elements, `ElementByName(e, 'EDID - Editor ID')` is nil, and a save writes only what the script adds (`Add Prefix Plus Name To EDID.pas` does this to 850 records of `Skyrim.esm`: 697 `KYWD`, 2 `LCRT`, 69 `AACT`, 82 `ACTI`; the GUI masks it by building the references at load, where every record's first init is a full one).

The port collapses the storage from the elements before it releases them (`MainRecordImpl::collapse_storage_after_quick_init`), so the record keeps its data and gains its required members, and the references its `VMAD` or `NAME` holds stay in the index.

Witnessed by `probes/edid-quick-init.pas` (the case reads every record through `ElementByName` first, equal) and the unit test `the_quick_init_keeps_the_subrecords_upstream_loses` (the name-first read); `Add Prefix Plus Name To EDID.pas` is a `known-difference` with this reason (`accept` in `runs.json`).

Found by the `sse-filters` regression (issue #64), where the loss emptied the `ACTI` whose script properties reference two persistent doors.
- **The string and slot model.** Strings are UTF-8 bytes: `Length('héllo')` is 6 where the oracle counts 5 UTF-16 units, and a `string`/`Char` variable is the one `varUString` kind where upstream's holds a `varString` (`VarType` 256; `Ord(s)` reads the character there).

A `string` parameter holds the caller's `varUString` upstream, which cannot be indexed (`aText[i]` raises `Array type required`; copy it into a local variable or use `Copy`), where the port indexes every string (`e-ordidx-*.pas`); `Ord` of a one-character `varUString` is its integer conversion on both sides (`Ord('7')` is 7).

A `Cardinal` result is carried as an `Int64` (20 against upstream's `varLongWord` 19), a never-assigned `Double` is the double 0 where upstream holds the `Currency` 0, the custom variant type codes are allocated per kind and not per first use (`sl.ClassType` reads 278 upstream, 279 in the port), and a `TList` item keeps the value's kind where upstream stores the pointer (277).

The variant operators themselves are upstream's, including the `'x' + 5` / `'x' + True` `Type mismatch`, and an empty variant (a missing `GetElementNativeValues` path, an unassigned or `Null` variable) compares against an integer as the oracle's does, so an `if` on such a comparison gets its boolean (probes `x-399`, `x-400`).
- **Regex.** `TPerlRegEx` runs the port's own PCRE engine (`crates/xedit-core/src/pcre.rs`, the RTL class in `crates/xedit-core/src/perl_regex.rs`, shared by the script adapter, Sniff's search-and-replace/tweaker and the filter's `CheckValueRegex`): lookaround, in-pattern backreferences, possessive quantifiers and atomic groups, ASCII `\d`/`\w`/`\s` without `PCRE_UCP`, `\Q..\E`, POSIX classes, inline flags, conditionals and PCRE's own compile errors with their offsets, all as the release build answers them. `preNotBOL`/`preNotEOL`/`preNotEmpty` are implemented as `PCRE_NOTBOL`/`NOTEOL`/`NOTEMPTY`, but no script can set them (upstream registers no `State` property either).

Not implemented, and a compile error where PCRE compiles the pattern: recursion `(?R)`/`(?1)`, `\N{name}`, `\K` and the `(*VERB)` control verbs; `\p{...}` covers the common properties through Rust's character classes, which is not the same Unicode version as the release's tables.

The check is `cargo xtask parity script --script "Regex probe" --phase run`: the probe lives in `crates/xtask/oracle/scripts/probes`, runs over the harness's empty master on both sides and prints offsets and lengths, never a multi-byte text (a value with a byte outside ASCII would depend on the code page the GUI writes its log in).
- **JSON dates and streams (closed by parity #30).** `TJsonBaseObject.LoadFromStream`/`SaveToStream` go through the JVCL `Classes` stream objects, the `UseUtcTime` conversion applies the machine's time zone, `D[]` parses the library's whole date surface and the `jdtUtcDateTime` distinctions are in the model (no registered member creates one: the adapter registers no `UtcDateTime` constant or member).

Compared equal by `cargo xtask parity script --phase run --script probes/` over `crates/xtask/oracle/scripts/probes/streams.pas` and `datetime.pas`.

What still differs there: the access violation of a nil stream names zero addresses where the GUI prints the faulting ones, a `TBinaryWriter.Write(string)` of a non-ASCII *script* string (a `#233` escape is one byte in the port's byte strings and the character U+00E9 in the GUI's, which its writer encodes as UTF-8), a released stream refuses with `EAccessViolation` where upstream reads freed memory, and a JSON parse error's message: the class and the failure match, but where the library's tokenizer names a token the port's direct parser names its own expectation (the oracle says `Expected "{" but found identifier (1, 2)` for a stream loaded from a position inside the document; `Unexpected end of file where value was expected (1, 9)` is the shape both give).
- **The abort line's class.** A raised data-format error prints `[EJvInterpreterError]` as its class where the GUI prints `[Exception]`. (The `External error in unit ...` wrapper of an earlier tip was removed by the run-parity fixups: a non-interpreter exception prints its bare message with the recorded `unit <unit> line <n>` as the outer location, and an interpreter error's outer location is the cleared `unit  line -1`, both as the oracle prints them.)
- **Runaway recursion and the native stack.** Interpreted calls are guarded at 128 deep and raise the oracle's `[EStackOverflow] Stack overflow` shape; upstream has no guard and dies on its own native stack below 1000 (the oracle runs 100 deep, probes `e-rec-*`), so the guard is a synthetic cap no legitimate script reaches.

The expression stack is modelled to upstream's boundary instead: `cJvInterpreterStackMax` holds 199 operands per expression and a flat expression of 202 operands raises `Expression is too complex - overflow` where 201 does not; parentheses, unary operators and a caller's pending arguments each push, as upstream (`e-flat-*`, `e-call-*`, `e-nest-*`).

A parse runs on its own 64 MiB thread (nesting cap 1024) where upstream recurses on the native stack.
- **Elapsed time and the save clock.** The origins are upstream's: the `[mm:ss]` prefixes count from the load's start (`wbStartTime`, re-set when `--build-refs` builds the references, `BuildAllRef`) and the `Done:` line's `Elapsed Time` from the `Applying script` action's own start (`PerformLongAction`'s `wbLocalStartTime`) -- the two runs' absolute values still differ by their wall-clock seconds, which the harness strips.

The `.save.<timestamp>` suffix is the local clock (`Now`), not UTC; the parity harness still normalizes its digits (the two runs saved seconds apart).

The closing line's `Processed Records` segment appears exactly when `Process` ran for at least one element, as upstream.
- **Resources.** `LoadFromResource` reads through the container handler, which a load fills only where a plugin's string tables need the archives, so a resource inside the game archives is not always found (load a localized plugin such as `Skyrim.esm` to have them listed).
- **No-ops and refusals where the GUI exists.** `Free` of a data-format root releases the document (a later call fails with `The file has been freed`; upstream is a use-after-free), `Free` of a non-root does nothing; `O2V(nil)` is `Unassigned`; `MoveUp`/`MoveDown`/`CanMoveUp`/`CanMoveDown`, `InsertElement`, `AssignTemplate*`/`TemplateAssign` and `ElementAssign` run the session commands `elements.move` and `elements.assign` and change the data as the view's Move Up/Move Down and drag and drop do.

The element states are the interpreter's own (`SetElementState`/`GetElementState`/`ClearElementState` over `IntToEsState`'s whole range, `esHidden` and the sort keys included, `esDummy` for anything else) and `ContainerStates` answers `TwbContainer`'s mask; `SetEditValue` of a main record runs upstream's gates and, without `wbDisplayLoadOrderFormID`, raises `FormID can only be edited if wbDisplayLoadOrderFormID is active`; `FileWriteToStream` writes the save bytes into a `Classes` stream with the `TwbResetModified` the third argument names.

The OS errors are upstream's routes: `TdfElement.LoadFromFile` raises `EOSError` with `RaiseLastOSError`'s text (`System Error.  Code: <n>.` and the system text on the next line), `TdfElement.SaveToFile` `EFCreateError` `Cannot create file "<path>". <system text>`, `TdfElement.LoadFromJSONFile` `EFOpenError` `Cannot open file ...`, and a bare `Exception` reads `[Exception]` in the abort line (not `[EJvInterpreterError]`, which only an interpreter error carries). `SetLength` resizes arrays and strings as upstream does for the element kinds it handles; an `array of string` raises `Array to array assignment` where upstream faults on the raw reallocation (`a-04`), and `SetLength` of a string variable resizes it where upstream's leaves the variable empty (`a-21`).
- **Minor host behaviours (parity #31).** `Beep` is `MessageBeep(0)` (the effect is audible, nothing a script reads); `ShowException` is the RTL's `MessageBox` titled `Application Error` with `OK` in the headless VCL model (parity #41): a recorded answer (`{"class": "#32770", "title": "Application Error", "button": "OK"}`) closes it and the run goes on, as the release's does once its box is closed, and without one the run stops with the question (`pending_interaction`); `DiskFree`/`DiskSize` are the volume API with the JvInterpreter wrapper's `Integer` truncation and the wrapped `Byte` drive argument (`DiskFree(300)` reads the drive 44); `GetLocaleStr`/`GetLocaleChar` read the system's locale (the machine is en-CA, so `GetLocaleStr(0, 31, ...)` is `yyyy-MM-dd`), `GetLocaleChar` answering the first character of values up to four characters and the default beyond that, a NUL for an empty value; `CreateProcessWait` is `CreateProcessW` with upstream's `STARTUPINFO` and `lpApplicationName` (a name without a path resolves against the current directory only, `cmd.exe` fails where a full path runs); `SetRoundMode` reaches the `MXCSR` rounding bits (which the RTL's `Round` and even `0.1 + 0.2` follow) and `SetPrecisionMode` the x87 precision field (no effect on x64 SSE results, as the oracle shows); the default `ShortDateFormat`/`LongTimeFormat`/separators are the locale's (`DateToStr` prints `2026-10-16` on the reference machine, `TimeToStr` `3:07:42 PM` with the locale's own AM/PM strings through the `AMPM` token; the format specifiers are read case-insensitively), while the day and month names stay the port's table.

The text-to-number conversions (literals, `StrToFloat`, the variant string reading, the JSON number tokens) run outside the mode `SetRoundMode` sets, as the oracle's do, so `0.1 + 0.2` under `rmDown` adds the nearest `0.1` and `0.2` and rounds the sum down.

The float-to-text conversions round in the mode too (fix-numerics: `FloatToDecimal`'s `Power10`, `Round` and division by ten are `MXCSR` operations in the oracle; the port replays each one in the script's mode, so `sys-round.pas` prints digits in all four modes). `ContainerStates` answers 1031 for a container `DoInit`ed and held, 1026 for one read once and reset (`csInitOnce` stays: a record's `EDID`, which the record's own init reads), 1024 for one never read; a main record or a subrecord is held while a script references one of its elements, a value (the record header) while the script references it.

The resets follow the releases (issue #69): a value read and let go while another member holds its record answers 1026, and the release of the last reference into a main record resets the record, whose members start unread again (1024, the `EDID` 1026).

Incomplete: `GetLocaleStr` for a value outside ASCII (type 119, the per-mille sign) follows the string model above. `TwbBGSMFile`/`TwbBGEMFile` `ToJSON` and `SaveToJSONFile` raise `Exception` `Not implemented` before they touch the file, as upstream does for materials.
- **The host functions (parity #25).** `ExecuteCaptureConsoleOutput` returns its `Cardinal` as an `Int64` (`VarType` 20 against 19, the slot model above); a function that returns the nil interface (`AddNewFile` cancelled, a lookup that finds nothing) holds `Unassigned` (`VarType` 0 against upstream's `varUnknown` 13; `Assigned` and the element functions read it the same); `wbRecordDefMap`'s objects are the port's definitions, not upstream's pointers.

Upstream bugs not reproduced: an `external` function with an argument or result type `CallDllIns` refuses faults the release (its handler re-raises a freed exception object) where the port raises `Invalid type of argument/result in call to function '<name>'` (probes `host-extfun-double`/`host-extfun-result`, `known-difference`), and `ExecuteCaptureConsoleOutput` copies its command line into a `MAX_PATH` buffer upstream (a longer one overruns the stack) where the port passes it whole.
- **Front-end limits.** A routine body terminated by the unit's `.` (`function P: integer; begin end.`) is refused (`';' expected but '.' found`), so two of `FunctionIsEmpty`'s six spellings are unreachable in practice; `xEditAPI.pas` is stubbed at run time even when the folder holds it, as upstream; `-scripthost:` names the script host on the legacy command line (only `JvI` exists; any other value fails with `xeDoInit`'s text).

Script and unit files are read as `TStringList.LoadFromFile` reads them (byte order marks, the ANSI code page, CRLF — the line numbers count those line breaks), and the message log is written in the ANSI code page.
- **Numbers.** `StrToFloat` is the RTL's `InternalTextToFloat` (`xedit_core::delphi::str_to_float`, ported from the machine code by fix-numerics, issue #67): the text ends at its first `#0` as a `PChar` does (`'1'#0'.5'` is 1), only spaces are blanks (a tab is refused), the digits go into an unsigned 64-bit accumulator up to `$1999999999999990` and then into a double as `(value * 10 + Ord(ch)) - 48`, the exponent stops reading above 1024 (`1E1000` is `INF`, `1E9999` is refused, `1E-1000` is 0), the scale is the RTL's paired-table `power10` under the default control word whatever `SetRoundMode` set, and a text that is no number may be one of the words `NAN`, `INF`, `+INF`, `-INF` (case-insensitive, as a whole: `Infinity` and `-NaN` are refused); a malformed text or an overflow raises `EConvertError` with `'<text>' is not a valid floating point value`. `FloatToStr`/`FloatToStrF`/`Format` print `FloatToDecimal`'s digits with the RTL's exponent padding (`FloatToStrF(1e22, ffExponent, 17, 0)` is `1.0000000000000000E+22`; `0.1` is `1.0000000000000000E-1`), and those digits round in the mode `SetRoundMode` set (`0.3` prints `2.9999999999999994E-1` under `rmDown`). `FormatFloat` is the RTL's `FloatToTextFmt` (`delphi::float_to_text_fmt`): the digits are `FloatToDecimal`'s rounded half up on the digit string (`FormatFloat('0', 2.5)` is `3`, `FormatFloat('0.00', 0.125)` is `0.13`), a value of 18 or more integer digits without an `E+`/`E-` in the picture is `FloatToStr` (`FormatFloat('0', 1e17)` is `1E17`), the minus sign is written only by the first section, the exponent of a zero is minus the integer placeholders (`FormatFloat('0.00E+00', 0)` is `0.00E-01`) and pads to at most four digits. `SameValue` uses the RTL's `1E-12` resolution; `Round` and `Trunc` keep the low 32 bits of the x64 integer indefinite for NaN and out-of-range values (`Round(NaN)` is 0, `Round(1e19)` is 0), `Ceil`/`Floor` are `Trunc` + `Inc`/`Dec` on `Frac` (`Ceil(1e10+0.5)` is 1410065409), and the `Math` constants are the release's (`MinDouble` the smallest normal, `NaN` `0xFFF8...`).

Parity #39 probed all of these (`probes/numerics.pas`, `probes/numerics-parse.pas`). `Frac` of NaN/`INF`/`-INF` is the oracle's `0.0000000000000000E+0`, an upstream quirk the port now reproduces (`Int` of the same values prints `NAN`/`INF`). `dfStrToFloat('NaN')`, `ArcSin(2)` and `ArcCos(-2)` are the RTL's `0xFFF8...` real indefinite (fix-numerics).

Owed: `0.0/0.0` raises a division error in the port where the oracle gives NaN (issue #28).
- **Front-end limits.** A routine body terminated by the unit's `.` (`function P: integer; begin end.`) is refused (`';' expected but '.' found`), so two of `FunctionIsEmpty`'s six spellings are unreachable in practice; unit files are read as bytes (no encoding detection); `xEditAPI.pas` is stubbed at run time even when the folder holds it, as upstream; `-scripthost:` is not read (only `JvI` exists).
