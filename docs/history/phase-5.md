Step 1 (archives) landed on `phase-5-assets` (Sonnet 5.5, 2026-10-08).

It ports the rest of `wbBSArchive` (`TwbAsset`; `TwbBSArchive` reading and writing every BSA version, Morrowind and general BA2 version, with the DX10 file table; `TwbSplitPacker` and `TwbMultiSourcePacker`), LZ4 and LZ4F compression and zlib above 8 MiB (`wbCompression`, from the C libraries upstream links: lz4 1.10 and zlib give the oracle's bytes), the BSA, BA2 and xxHash hashes of `wbHash`, the resource listings and hash tables of `wbBSA` (`container_handler.rs`), the console tool of `BSArch.dpr` as the `bsarch` binary with the upstream arguments and text, and the commands `archive.list`, `archive.extract` and `archive.pack` (`xedit archive list|extract|pack`, with `--dry-run` and the `--edit` gate).

The code is `crates/xedit-io/src/archive/` (`mod.rs` reading and listing, `write.rs` the creation, `packer/` the packers and the unpacking, `asset.rs`, `texture.rs`), `crates/bsarch`, `crates/xedit-session/src/archive.rs`. *Determinism.* Upstream packs on a thread pool and the data of an archive lands in the order the threads finish; the oracle is `BSArch.exe -mt:no`, which is one thread.

The port reproduces that single thread's steps on any thread count: the reading, hashing and compressing of the files runs ahead on the pool (a window of files and 512 MiB), and the decisions that depend on the order (the files that share data, the split into archives from the compressed sizes, the order the data is written in, `fProcessTick mod 3` of the loading and writing steps) are made in upstream's order as the results arrive.

Two quirks make `-mt:yes` and `-mt:no` differ upstream: the Morrowind list is sorted by name only without threads (the port always sorts), and the data order is a race (the port takes the single thread's). *Texture archives.* Everything that looks inside a DDS file or builds one is the extension point `archive/texture.rs` (`chunk_dds`, `pack_dds_chunks`, `pack_dds`, `unpack_dds`, each failing with `Texture (DX10) archives are not supported yet`); `create_archive` and `save` already reserve and write the DX10 file table, `pack_chunk` takes any chunk, and the file table, `-dump` and the format names of the DX10 archives read and print like the oracle's.

The gate evidence is `cargo xtask parity bsarch`: for each archive of the game folders (the 363 archives of 11 games up to `--max-size` MB, 40 by default, or the ones named with `--archive`) it compares the `-dump` text of the oracle and the port, the files `unpack` writes, and the archives `pack` writes from the unpacked folder (the oracle with `-mt:no`; the port with all threads and with `-mt:no`; every compression of the source's format, and the text of the run), plus `--synthetic` for what the game archives do not cover (two source folders and an archive merged, filters, flags, `-split`, files without data, names that sort several ways, identical files, textures only, a name with accents).
